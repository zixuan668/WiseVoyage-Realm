# 智游知境 · 固定景区数字人服务站

## 产品定位

Web 提供固定点位的现场接待：了解景区、咨询问题、从本站规划游览、查找景点、已发布的设施和出口、扫码领取方案。设备不跟随游客移动，不启用游客 GPS，不按到点自动播报。手机网页承接移动游览；App 复用领取和游览接口。后台统一维护资料与点位。

本分支 `web` 基于 LZX；分支初始提交 `3e8574a` 也包含当时尚未提交的路线顺序优化。LZX 分支引用未移动。

## 页面入口

- `/`、`/station`、旧桌面 `/visitor/home`：进入默认服务站。
- `/station/summer-palace-east`：东宫门示范站。
- `/station/:stationId`：其他已启用点位。
- `/station-preview/:stationId`：1920×1080、1280×800、1080×1920 的已发布屏幕预览。
- `/login`：管理登录；`/stations`：服务站配置，需要管理员。
- `/m/receive#claim=...`：领取页。凭证置于 fragment，不进入网页服务器 URL 日志。
- `/m/home`、`/m/tour/:sessionId`：手机规划和游览。

游客不用登录或先选择数字人。首页是接待入口，展示实时数字人、景观和四项任务。左侧数字人进入页面即连接，占据整列；不以静态封面代替实时形象。连接失败时提供重试，文字与路线功能仍可用。页面沿用原有的白底、紫色与全局中英文字体，移除装饰标语、卡片副标题和编号。咨询阶段以简短回答、对应图片、时间线和下一步按钮服务游客；路线问题整理为可确认的规划表。讲解可以打断，可以只看文字。云端数字人使用本次服务站凭证连接，不创建或推进手机游览。

四项任务为游览规划、游园须知、景点与设施、景区介绍。咨询入口统一放在左侧数字人下方，避免首页重复。游园须知包括开放时间、票务、游园提醒与后台已发布公告，支持中英文和官网二维码；查看须知不依赖咨询接口。当前颐和园开放与票务参考来自[官网导览页](https://summerpalace.net.cn/visit.html)，核对日期为 2026-10-18，记录在 `frontend/src/data/parkVisitorInfo.ts`。默认按北京时间选择淡旺季，可手动切换；停止入园与闭园时间分别展示。这些是有来源的参考资料，不是实时开放、余票或票务交易接口；临时变更仍以官方渠道和现场为准。本站没有公告时只表示本站未发布，不代表景区没有临时安排。

## 固定起点与路线

服务站起点由管理员从现有 OSM 步行路网接入点选择，支持门区或景点旁点位。`station_anchor()` 使用实际节点，`route_overview()` 和顺序优化同时接受内部传入的起终点节点。地图绘制同一批道路几何，标注本站起点。

规划表只保留可核对的路线条件：游览时间、自选景点、结束位置、是否避开已标注台阶。移除主题和游览节奏选项，对话不再根据“老人、亲子、摄影”等词推断隐藏偏好。前端仅提交这些条件和语言，也不把旧接口返回的主题、节奏字段写回本次规划。

预算包含本站到首站、景点间步行、末站到终点、景点停留和休息。本站统一使用 75 m/min 的步行估算；台阶选项只避开地图已标注的台阶，不承诺无障碍。终点为指定出口或回到本站。没有完整路径时明确失败，绝不补直线。

单点寻路以“地图＋路线概览”展示，A/B 标记对应本站和目的地。概览只保留按行走顺序出现的主要道路名称，合并连续重复名称、隐藏未命名碎路段和每个碎片的米数；较长的主要路段列表按需展开。总距离与用时仍使用完整路径计算结果，台阶提醒仍检查全部路段。概览不是逐转向导航，不推测路口转向，也不把道路名称当作已经实测的景点停靠点；底层路线几何不因展示简化而改变。

自动规划在最多 16 个已接入景点中进行有界搜索，每层最多 72 个候选，最多 8 站：主推荐最多 6 站；“少走一些”必须比主推荐少走且不增加总时间；“多看一些”必须增加景点。不能产生有效差异时不显示对应备选。再用现有顺序优化器整理选中的顺序。此搜索不宣称自动选点全局最优。

自选景点保留全部选择并优化顺序；超预算时要求调整，不能静默删点或压低步行时间。方案有起终点、逐站顺序、时间组成和资料版本。需求改变、路网改变或配置改变后，需要重新计算才可领取。

## 会话与领取

新增独立数据表 `service_station`、`station_visit`、`station_plan`、`station_claim`，由现有启动建表机制创建。不覆盖原有景点、路线、数字人或历史游览资料。

1. 配置数字人的服务站进入页面即创建短期匿名咨询并连接实时形象，访问令牌只保存在页面内存；数据库只存令牌哈希。服务有效期 30 分钟，网页保持连接期间延长。未配置数字人时仍可在点击任务后创建咨询。
2. 对话最多保留 12 条，历史仅用于本次接待。结束立即清空对话并撤销咨询凭证，删除未领取的临时方案。
3. 点击任务后才开始无人操作计时，默认 120 秒，结束前 20 秒提醒，可继续使用。首页只展示实时数字人时不会反复弹出超时提醒。结束使用清空对话和选择、撤销旧凭证，再以新凭证连接接待形象。讲解、语音识别和计算中不自动清空。录音识别有 20 秒上限，单次播放有 120 秒保护，防止异常状态阻塞复位。
4. 临时方案一小时有效。领取码 15 分钟有效，二维码由前端本地生成，未调用外部二维码服务。
5. 领取码保存独立方案快照，大屏结束不删除它。领取时锁定记录并在同一事务创建手机游览，保留景点顺序、语言、路线条件、本站起点与终点。
6. 同一领取凭证与手机回执重试会返回同一个会话；其他回执不能重复领取。不会把大屏聊天历史复制到手机。
7. 领取和分享检查服务站版本、景点路线资料版本及路网版本。版本变化时要求重新规划。

手机端仍使用已有的移动导览能力。服务站页面不请求浏览器位置；手机定位仍由游客主动启用。旧桌面导览链接保留兼容，正常服务站流程不进入它。

## 后台与信息边界

管理员可新建点位，维护中英文名称与位置、数字接待员、欢迎语、默认语言、复位时间、本地语音音量、启停、公告和设施。保存采用版本校验，避免覆盖其他管理员的更新。已发布设备通过心跳检测版本，结束当前接待后加载新配置。预览页可检查完整屏幕；编辑页单独预览未保存的接待文案。

默认东宫门是**示范点位**，展示示范标识。发布正式点位时须核实设备与步道接入点的关系，不能将随意坐标吸附到路网上冒充实测。现有路网没有覆盖的设备位置，要先补充并核实道路数据。

设施必须有资料来源和已核实标记才会公开；暂不可用的设施禁止计算路线。默认未填充未经确认的厕所、饮水点。出入口的路网信息也不代表即时开放。公告有效期需包含时区。设备“近期在线”表示网页心跳，不能代替现场硬件诊断。

模型限时调用，超时保留本地景点资料回答；英文缺少模型服务时使用已存在的公开英文资料。语音失败可以继续读字幕，路线和文字服务不依赖云端数字人成功连接。云端数字人的音量仍由其播放器或设备设置控制，后台音量配置用于本地语音。

## 运行与现场部署

当前本地前端 5173、后端 8001。前端 `VITE_BASE_SERVER_URL` 指向后端。新增 `/service-stations` 与现有 API 一样需要反向代理；生产页面路由使用 SPA 回退。

正式现场建议使用稳定 HTTPS 域名，服务站和手机访问同一业务入口。localhost 体验下二维码使用检测到的局域网 IP；手机必须能访问该地址。演示可先用手机网页承接，App 接入流程见 app-pickup.md。

Windows 设备可把站点配置为 Edge 全屏自助终端。开机自启、操作系统锁定、麦克风授权、网络与供电保障、方向指示和现场位置核验属于设备部署，需要在实际设备上完成；本次代码不会修改电脑的登录、启动项或系统权限。

只缓存公开景点资料和公开页面资产，不缓存会话、管理 API、领取凭证和语音。断网时可浏览此前加载的公开资料，不能继续在线咨询、计算新路线或领取。底图依赖网络加载，不承诺完整离线导航。生产 service worker 仅缓存白名单；开发环境不新注册它。

# App 领取路线后选择数字人

App 扫码或输入领取码后，先通过登录保护的 `POST /service-stations/claim/preview-app` 读取路线，并展示可用数字人；预览不会消耗领取码，也不会默认选中服务站的接待员。用户选择人物并点击“开始导览”后，才提交 `POST /service-stations/claim/receive-app`，请求体必须包含正整数 `guide_id`，以及原有 `token`、`receipt`。

服务端校验人物已上架且可用，再创建或恢复本人拥有的导览；景点顺序、路线与时间设置保留。本人重新扫码后明确改选人物时复用原导览及进度，并清除上一人物的视频路径；已结束的导览不能通过领取码重新启动。独立网页领取接口保留原有行为。
