# App 选择数字人页：单人卡片居中与开始导览响应

反馈：手机领取路线后的“选择数字人”页只显示一位人物时，人物卡片贴在左侧；点“开始导览”没有任何反应。截图对应当前领取页（路线“十七孔桥 → 仁寿殿”，按钮依次为开始导览、重新扫码、暂不开始）。

## 原因

- 人物卡片容器固定为两列网格。只有一位可选人物时，卡片只占左列，右侧留空，看起来没有居中。
- “开始导览”按钮在原逻辑里带 `disabled="... || (snapshot&&!pickedGuideId)"`。页面为了不默认选中服务站接待员，初始不选中任何人物，因此按钮一直是 disabled；禁用按钮不触发点击，也不显示错误，表现为“点了没有用”。

## 修改

只改 App 领取页与其源级回归测试，不改网页、后端和接口。

- 人物卡片容器改成可换行的居中 flex 布局，卡片仍按两列宽度排列：一位人物时卡片居中，三位等奇数时最后一行也居中。
- 只有一位可选人物时，点“开始导览”视为选择该人物并直接领取，不再需要多点一次；多位人物时仍需先选，未选就点会显示“请先选择数字人”提示并保持页面不动，不会创建重复导览。
- 多位人物且未选择时，按钮不再禁用，可以点击并给出提示，不会创建导览，不再是没有任何反馈的状态。
- 没有可用人物时点击提示“暂无可用数字人，请稍后重试”。
- “开始导览”不再用深紫底白字（`#4f46e5`），改为截图指定的浅紫软色：背景 `var(--ng-raised,#f0edf8)`、文字 `var(--ng-secondary,#4b5563)`。软色板里 `--ng-raised` 在设备上是 `#eef2ff`，源码兜底为反馈截图中的 `#f0edf8`；可点击、未选择和处理中统一为这同一个浅色。
