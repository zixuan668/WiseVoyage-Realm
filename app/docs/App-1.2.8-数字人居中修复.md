# App 1.2.8：数字人居中修复

只修改 App。main 的 Web 和后端未改动；保留原有数字人解码及路线调整修复。

## 原因与修改

导览中星云数字人的容器还保留 `translateX(-10%)`，导致画面整体向左偏移。在 320 px 视口中，实际容器中心偏左约 31.2 px。另外，打包的 SDK 会按资源布局写入像素宽高、缩放、边距和横向偏移；仅修改外层居中，无法保证内层画布完整显示。

去掉外层负偏移，设置相对定位容器；对内部 canvas 使用与只读 LZX Web 相同的显示规则：铺满可用容器、清除 SDK 的显示位移和缩放，使用 `object-fit: contain` 和 `object-position: 50% 50%` 等比例完整显示源画面。不修改画布像素分辨率、模型资源、SDK 解码、连接与音频逻辑。

App 编译器会把 CSS 的 `canvas` 类型选择器改写成 `uni-canvas`，无法匹配 SDK 动态创建的原生 DOM canvas。使用 SDK 初始化画布时写入的固有 `[width][height]` 属性匹配，并限定在导览数字人容器中；编译后的 CSS 也必须通过布局检查。

## 验证

- 修复前用 App 原 CSS 和实际打包 SDK 的 `setCanvasStyle` 方法复现容器偏左。
- 修复后在 320×640、390×844、844×390、768×1024 四种视口中，分别运行居中、左对齐带偏移、右对齐带偏移三种 SDK 配置，共 12 个组合；检查画布与显示区域的中心、边界、等比显示规则，包含窗口尺寸变化与 SDK 重写样式。
- 同样检查编译后的 App 原生页面 CSS，以确认 scoped 样式可作用于 SDK 动态创建的 canvas。
- 原有 19 项自动检查通过。记录在 `app/unpackage/main-d31183c-1.2.8/avatar-layout-results/`。
- 上述布局测试使用合成画布与实际 SDK 布局方法，没有发起真实数字人会话；未连接 Android 真机，不能视为真实人物画面或真机验证。

## 手机复查

覆盖安装 1.2.8 后，退出旧导览并重新选择数字人开始导览。检查待命和说话状态的横向位置，进入“路线与用时”再关闭后检查位置是否保持；若设备支持横屏，旋转后再检查。人物源画面等比例显示，上下或左右可能留白。如果资源本身的人物画在画面一侧，属于源画面取景，需另外对照实际截图分析，不通过整体挪动所有数字人来补偿。
