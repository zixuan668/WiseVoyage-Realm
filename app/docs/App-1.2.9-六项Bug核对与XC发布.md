# App 1.2.9：六项 Bug 核对与 XC 发布

基于 main `d31183cf5bd3ca9948d1c7fbf85b091a91368ee8`；本次产品修改全部在 `app/`，Web、后端和共享坐标模块不改。保留 1.2.4–1.2.8 的数字人兼容、动态路线、滚动地图、重叠高亮和居中修复。

用户截图中的修复清单在切换回 main 底版后，并未全部保留；本次以当前源码重新核对、补齐并验证。

| 核对项 | 1.2.9 实现与验证 |
|---|---|
| 普通问题返回路线推荐 | AI 小导游默认“景点问答”，选择问答景点；通过现有游客会话的 `PUT /tour-session/chat` 提问。只有“路线规划”使用推荐接口，照片识景后也可以继续问答。语言按 App 设置和问题识别传入。 |
| 预览时长不一致 | 显示服务器的 `estimated_time_minutes / total_duration` 和相邻站点的步行数据，缺失时显示待配置，不用直线距离估计。采用路线后保留服务器顺序、预算和步行节奏。 |
| 清空后旧回复再次出现 | 通过请求代次和账号核对拦截迟到文字、照片、景点目录及语音识别；清空停止播报和录音，清除草稿及路线状态，取消延迟采用导航。图片选择器迟到也不会恢复旧草稿。 |
| 不同账号混用聊天 | 以用户 ID（或用户名）区分本地历史；切换账号时重置会话，旧账号在途响应不能写入新账号。没有归属的旧共享聊天不迁移。采用路线的临时交接也校验账号。 |
| 输入默认仅 140 字 | 明确设置 2,000 字上限；发送时再次校验，空消息不发送。照片附言遵循现有后端 1,000 字限制。 |
| 重新进入后状态丢失 | 按账号保存最近 200 条消息、问答/规划模式、所选景点、问答会话和服务端路线结果；重新进入时恢复，追问使用原会话。失效会话按既有接口重建一次。 |

## 验证记录

- `node --test app/tests/*.test.cjs`：29 项通过，包含新增 9 项 AI 聊天检查与路线交接检查，以及原地图/数字人检查。
- `ai-chat-browser.cjs`：使用编译后的 App 页面，模拟接口验证问答接口与英文参数、服务端时间/步行数据、刷新恢复、会话复用、清空后迟到响应、输入 1,500 字及 2,000 字上限。属于浏览器模拟验证。
- `route-browser.cjs`：编译后的 App 路线顺序、预览/采用、三类地图弹层滚动与完整路线边界回归通过；接口和底图图片模拟。
- `real-qa-check.py`：真实本地后端中创建独立匿名测试会话，两次英文问答复用同一会话，服务端返回 `language=en`，会话记录持久化；测试会话已结束。没有把数据库/本地知识回答说成云模型回答。
- 原生编译、编译后 CSS 布局及 APK 资源/签名另存 `app/unpackage/main-d31183c-1.2.9/` 与 `app/unpackage/releases/1.2.9/`。这些产物被 Git 忽略，不包含在源码提交中。
- 尚未完成 Android 真机验证、真实照片识别及真实语音录制联调。
